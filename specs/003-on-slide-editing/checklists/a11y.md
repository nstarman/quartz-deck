# Accessibility (T033, FR-017) — checked 2026-11-04

- [x] Keyboard path through elements: Tab / Shift+Tab in the slide move the
      selection (status line announces "Selected <kind> <ref>"); Enter edits,
      ⌥Enter edits source, Escape leaves an edit (element stays selected) and
      Escape again deselects — `fragments_notes_and_keyboard_selection`.
- [x] Every action is reachable without a mouse: Shift+F10 / ContextMenu key
      opens the menu for the selection or the slide; ⌘C/⌘X/⌘V/⌘D, ⌫, ⌥↑/⌥↓.
- [x] Menus: `role=menu`, `menuitem` / `menuitemcheckbox` with `aria-checked`,
      `aria-disabled`, `aria-haspopup`; arrows, Enter/Space, ArrowRight/Left
      for submenus, Escape; menus take keyboard focus and return it on close.
- [x] Accessible names: formatting toolbar, element bar and hover handles
      carry `aria-label`s (shortcut included); slide bar controls labelled
      (Transition, Hidden in the presentation, Background colour); PDF
      checkbox labelled — verified in the browser pane's accessibility tree.
- [x] Status messages go to a `role=status` live region; conflicts and
      render errors to `role=alert`.
- [x] Escape is never taken by Reveal (overview) inside the editor.
- [ ] Not done here: a screen-reader pass (VoiceOver) and colour-contrast
      audit of the bars — recommended before a public release.
